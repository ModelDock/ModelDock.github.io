Hardware Acceleration

Learn how ModelDock utilizes NVIDIA CUDA GPU offloading and multi-threaded CPU matrix operations to achieve high token generation speeds.

1. NVIDIA RTX & CUDA Auto-Detection

When launching inference, ModelDock inspects your system's hardware using the built-in system telemetry probe (core/system_monitor.py):

  • Automatic CUDA Activation: If an NVIDIA GPU (GeForce RTX, Quadro, or Tesla) with CUDA support is detected, ModelDock configures the inference engine to offload transformer layers directly to GPU VRAM.
  • Tensor Core Acceleration: Utilizes 16-bit floating point and INT4/INT8 tensor cores to accelerate prompt evaluation and auto-regressive decoding.
  • Zero Setup Required: ModelDock ships with the appropriate runtime bindings, eliminating manual CUDA Toolkit path configurations.

2. GPU Layer Offloading (Hybrid Inference)

If your model is larger than your GPU's dedicated VRAM, ModelDock supports partial offloading:

  • Full Offload: All transformer layers (e.g. 33 layers for 8B models) are loaded into VRAM. Token generation runs entirely on GPU at 50-120+ tokens/sec.
  • Hybrid Split: If you have 8 GB of VRAM and an 8B model needs 10 GB (model weights + 8k context), you can offload 24 layers to GPU and keep the remaining 9 layers in system RAM.
  • Configurable in Settings: You can set gpu_layers: -1 (all layers to GPU) or specify exact numbers (e.g. 28).

3. Estimating Required VRAM

Before loading a model, estimate total required VRAM using this rule of thumb:

Memory Formula

Total VRAM ≈ GGUF File Size + Context Memory Buffer (~0.5 GB to 2 GB)

Model Architecture Quantization GGUF File Size Suggested VRAM
Llama 3.2 1B / 3B Q4_K_M 1.8 GB - 2.4 GB 4 GB VRAM (GTX 1650, RTX 3050)
Llama 3.1 8B / Qwen 2.5 7B Q4_K_M 4.9 GB 8 GB VRAM (RTX 3060, 4060)
Qwen 2.5 14B Q4_K_M 8.9 GB 12 GB - 16 GB VRAM (RTX 4070, 4080)
Command R+ 32B / DeepSeek 32B Q4_K_M 19.8 GB 24 GB VRAM (RTX 3090, 4090)

4. CPU Multi-Threading Optimization

For systems without dedicated NVIDIA GPUs, ModelDock leverages CPU SIMD vector extensions:

  • Instruction Sets: Compiled with support for AVX, AVX2, AVX-512, and FMA3.
  • Physical Core Detection: Automatically defaults thread count to match your CPU's physical cores (e.g. 8 threads on an 8-core / 16-thread CPU). Hyperthreading / SMT threads can cause cache thrashing in matrix GEMM calculations.
  • Thread Slider: Customize thread counts anytime in Settings → Compute & Hardware.
